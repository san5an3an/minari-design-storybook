# 20종 디자인시스템

자동 생성됨. 생성 스크립트 실행 결과이며 직접 편집 금지. 명세 원본은 별도 파일임

> 20종은 서로 독립임. 값을 공유하지 않고 교체나 조합도 하지 않음
> 아래 표는 각 시스템이 서로 얼마나 다른지 보여주는 것이며 공통 규격은 아님

## 설계 방침

색상만 20가지로 돌리면 같은 시스템의 테마 20개일 뿐임. 그래서 8개 기준을 함께 흩었음

| 항목 | 값 |
|---|---|
| 색상(hue) | 색상환 전역, 무채색 계열 |
| 채도 성격 | muted · balanced · vivid |
| 중립 온도 | 색상각, 채도(0.004~0.020)로 차갑거나 따뜻하게 |
| 형태(radius) | sharp · md · soft · round |
| 밀도(spacing) | compact · regular · airy |
| 타이포 비율 | 1.2 · 1.25 · 1.333 |
| elevation | flat · border · shadow · glow |
| control (폼 해부) | outline · filled · underline · soft |

팔레트 개수도 다름 (3~6종). elevation 성격에 따라 버튼 variant 구성도 다름 (3~5종)

- `flat` → solid · subtle · plain
- `border` → solid · outline · subtle · plain
- `shadow` → solid · subtle · surface · outline · plain
- `glow` → solid · subtle · surface · plain

컴포넌트 세트도 다름 (71종)

- Core 17종(`button` `link` `input` `label` `field` `select` `checkbox` `radio` `switch` `badge` `card` `dialog` `alert` `toast` `tooltip` `spinner` `divider`)은 20종 전부에 있음. 범용 디자인시스템의 필수 요소이기 때문임. 이름이 같아도 값이나 구조를 공유하지 않음. 같은 `input` 이라도 control, elevation, density, radius 기준이 달라 다른 구성이며, `generated/{slug}/vars.css` 없이는 변수가 해소되지 않음
- Signature 54종은 그 시스템의 성격(`tone`)에서 파생됨. 후보 54종은 후보 목록일 뿐 공통 규격이 아님

## 색상 생성 방식

- OKLCH로 생성하고 hex로 저장함. Figma 변수가 hex 기반이므로 값에 `oklch`나 `rgba` 를 남기지 않음
- 단계 9, 11, 12의 명도는 요구 대비를 만족하는 지점을 계산해서 정함. 검증 단계에서 나중에 잡는 게 아니라 애초에 위반이 나오지 않음
- 단계 번호는 명도가 아니라 용도임 (`9`=solid 배경, `11`=저대비 텍스트, `12`=고대비 텍스트)
- 다크 모드는 명도 반전이 아니라, solid를 밝게 하고 그 위 전경색(`contrast`)을 어둡게 뒤집는 방식임
